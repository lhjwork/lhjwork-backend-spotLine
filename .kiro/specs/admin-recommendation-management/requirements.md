# 관리자용 추천 관리 시스템 요구사항

## 프로젝트 개요

SpotLine 관리자가 매장별로 추천 관계를 쉽게 설정하고 관리할 수 있는 웹 인터페이스를 구현합니다. 오늘 개발된 이중 검색 API(거리 기반 + 지역 기반)를 활용하여 직관적이고 효율적인 추천 설정 기능을 제공합니다.

## 사용자 스토리

### 1. 매장 추천 설정 관리자

**역할**: SpotLine 서비스 관리자  
**목표**: 각 매장에 대해 적절한 다음 방문 장소를 설정하여 사용자 경험을 향상시키고 싶습니다.

### 2. 주요 사용자 스토리

#### US-1: 매장 목록에서 추천 설정 접근

```
관리자로서,
매장 목록 화면에서 각 매장의 추천 설정 상태를 확인하고
"추천 설정" 버튼을 통해 해당 매장의 추천 관리 화면으로 이동하고 싶습니다.
그래야 어떤 매장이 추천 설정이 완료되었는지 한눈에 파악할 수 있습니다.
```

#### US-2: 이중 검색으로 추천 후보 탐색

```
관리자로서,
특정 매장의 추천을 설정할 때
"근처 매장(10km)" 탭과 "같은 지역" 탭으로 나누어진 후보 목록을 보고 싶습니다.
그래야 물리적 거리와 지역적 특성을 모두 고려하여 최적의 추천을 선택할 수 있습니다.
```

#### US-3: 직관적인 매장 선택 인터페이스

```
관리자로서,
각 후보 매장을 체크박스로 선택하고
매장 정보(이름, 카테고리, 거리, 이미지)를 카드 형태로 보고 싶습니다.
그래야 어떤 매장을 선택하는지 명확하게 판단할 수 있습니다.
```

#### US-4: 추천 카테고리 자동 제안

```
관리자로서,
매장을 선택할 때 시스템이 제안하는 추천 카테고리를 확인하고
필요시 수정할 수 있는 드롭다운을 보고 싶습니다.
그래야 적절한 추천 유형을 빠르게 설정할 수 있습니다.
```

#### US-5: 기존 추천 관계 관리

```
관리자로서,
현재 설정된 추천 관계 목록을 확인하고
개별 추천을 수정하거나 삭제할 수 있는 기능을 사용하고 싶습니다.
그래야 추천 관계를 지속적으로 관리하고 최적화할 수 있습니다.
```

#### US-6: 일괄 저장 및 미리보기

```
관리자로서,
선택한 모든 추천을 저장하기 전에 미리보기로 확인하고
한 번에 저장할 수 있는 기능을 사용하고 싶습니다.
그래야 실수를 방지하고 효율적으로 작업할 수 있습니다.
```

## 기능 요구사항

### 1. 매장 목록 화면 개선

- **FR-1.1**: 매장 목록에 "추천 개수" 컬럼 추가
- **FR-1.2**: 각 매장 행에 "추천 설정" 버튼 추가
- **FR-1.3**: 추천이 설정된 매장과 미설정 매장 구분 표시

### 2. 추천 설정 화면 (신규)

- **FR-2.1**: 현재 매장 정보 표시 (이름, 카테고리, 주소, 지역)
- **FR-2.2**: 탭 기반 후보 매장 표시
  - "근처 매장 (10km)" 탭: 거리순 정렬
  - "같은 지역 (OO동)" 탭: 이름순 정렬
- **FR-2.3**: 각 후보 매장 카드에 다음 정보 표시:
  - 매장 이미지 (대표 이미지)
  - 매장 이름 및 카테고리
  - 거리 및 도보 시간
  - 주소 및 지역
  - 이미 연결된 매장 표시
  - 제안된 추천 카테고리 태그

### 3. 매장 선택 및 설정 기능

- **FR-3.1**: 체크박스를 통한 다중 매장 선택
- **FR-3.2**: 선택된 매장별 추천 카테고리 설정 드롭다운
- **FR-3.3**: 선택된 매장별 우선순위 설정 (1-10)
- **FR-3.4**: 선택된 매장별 설명 입력 (선택사항)

### 4. 기존 추천 관리

- **FR-4.1**: 현재 설정된 추천 목록 표시
- **FR-4.2**: 개별 추천 수정 기능
- **FR-4.3**: 개별 추천 삭제 기능
- **FR-4.4**: 추천 우선순위 드래그 앤 드롭 정렬

### 5. 저장 및 미리보기

- **FR-5.1**: 선택된 추천들의 미리보기 모달
- **FR-5.2**: 일괄 저장 기능
- **FR-5.3**: 저장 성공/실패 알림

## 기술 요구사항

### 1. API 연동

- **TR-1.1**: `GET /api/recommendations/nearby-stores/{storeId}` 연동
- **TR-1.2**: `POST /api/recommendations/selected/{storeId}` 연동
- **TR-1.3**: 기존 추천 CRUD API 연동

### 2. 사용자 인터페이스

- **TR-2.1**: 반응형 웹 디자인 (데스크톱 우선)
- **TR-2.2**: 탭 기반 네비게이션
- **TR-2.3**: 카드 기반 매장 표시
- **TR-2.4**: 로딩 상태 표시
- **TR-2.5**: 에러 상태 처리

### 3. 성능 요구사항

- **TR-3.1**: 매장 목록 로딩 시간 3초 이내
- **TR-3.2**: 추천 저장 응답 시간 2초 이내
- **TR-3.3**: 이미지 지연 로딩 적용

## 수용 기준 (Acceptance Criteria)

### AC-1: 매장 목록 화면

```
GIVEN 관리자가 매장 목록 화면에 접근했을 때
WHEN 페이지가 로드되면
THEN 각 매장의 추천 개수가 표시되고
AND "추천 설정" 버튼이 각 행에 표시되어야 함
```

### AC-2: 추천 설정 화면 접근

```
GIVEN 관리자가 특정 매장의 "추천 설정" 버튼을 클릭했을 때
WHEN 추천 설정 화면이 로드되면
THEN 현재 매장 정보가 상단에 표시되고
AND "근처 매장"과 "같은 지역" 탭이 표시되어야 함
```

### AC-3: 이중 검색 결과 표시

```
GIVEN 추천 설정 화면에서
WHEN "근처 매장" 탭을 선택하면
THEN 10km 반경 내 매장들이 거리순으로 표시되고
WHEN "같은 지역" 탭을 선택하면
THEN 같은 area 값을 가진 매장들이 이름순으로 표시되어야 함
```

### AC-4: 매장 선택 및 설정

```
GIVEN 후보 매장 목록에서
WHEN 관리자가 매장을 체크박스로 선택하면
THEN 해당 매장의 추천 카테고리 드롭다운이 활성화되고
AND 제안된 카테고리가 기본값으로 선택되어야 함
```

### AC-5: 추천 저장

```
GIVEN 관리자가 매장들을 선택하고 설정을 완료했을 때
WHEN "저장" 버튼을 클릭하면
THEN 미리보기 모달이 표시되고
WHEN 미리보기에서 "확인"을 클릭하면
THEN 모든 추천이 저장되고 성공 메시지가 표시되어야 함
```

### AC-6: 기존 추천 관리

```
GIVEN 매장에 이미 설정된 추천이 있을 때
WHEN 추천 설정 화면에 접근하면
THEN 기존 추천 목록이 별도 섹션에 표시되고
AND 각 추천을 개별적으로 수정하거나 삭제할 수 있어야 함
```

## 화면 구성 요구사항

### 1. 매장 목록 화면 수정

```
┌─────────────────────────────────────────────────────────────┐
│ 매장 관리                                                    │
├─────────────────────────────────────────────────────────────┤
│ 이름        │ 카테고리 │ 지역    │ 추천개수 │ 액션          │
│ 카페 스팟라인 │ cafe    │ 연희동   │ 3개     │ [추천 설정]    │

```

## 우선순위

### 높음 (P1)

- 매장 목록에서 추천 설정 접근
- 이중 검색 기반 후보 매장 표시
- 기본적인 매장 선택 및 저장 기능

### 중간 (P2)

- 기존 추천 관리 기능
- 미리보기 모달
- 드래그 앤 드롭 정렬

### 낮음 (P3)

- 고급 필터링 옵션
- 추천 성과 분석
- 일괄 작업 기능

## 제약사항

1. **기술적 제약사항**
   - 기존 관리자 시스템 UI 프레임워크 사용
   - 오늘 개발된 API 엔드포인트 활용 필수
   - 기존 인증/권한 시스템 연동

2. **비즈니스 제약사항**
   - 매장당 최대 10개 추천 제한
   - 추천 카테고리는 기정의된 6개 타입만 사용
   - 관리자 권한이 있는 사용자만 접근 가능

3. **사용자 경험 제약사항**
   - 모바일 환경에서도 기본 기능 동작 보장
   - 인터넷 연결이 불안정한 환경 고려
   - 대량 데이터 처리 시 성능 최적화 필요

이 요구사항 문서를 바탕으로 관리자 화면 개발을 진행하시면 됩니다!
